# OpenART 位置式直控输出对齐规格

## 执行状态

- 状态: Archive


## 背景

`SmartCar2026-Vision` 当前运行时在视觉侧完成目标选择、阶段判断与 P 环计算, 并通过串口持续发送平面速度请求。

当前底盘仓库已经切回稳定控制版本, `UART6` 上现成可复用的稳定入口是相对位置命令 `dx` / `dy` 配合 `lock=0` 的持续覆盖语义。若视觉仓库继续输出速度请求, 两边主线会长期错位, 联调时需要临时改口径或额外加兼容层, 这与当前“优先收口稳定链路”的目标不一致。

因此本轮设计将视觉仓库的主线输出收口为: 视觉侧继续负责目标识别、阶段判断与 P 环计算, 但最终串口载荷统一改为位置式文本命令 `dx=<dx>,dy=<dy>,lock=0`。

## 目标

1. 保持 `main.py` 单文件架构不变。
2. 保持视觉侧负责目标选择、阶段判断与 P 环计算。
3. 将串口主线输出从速度请求切换为位置请求 `dx=<dx>,dy=<dy>,lock=0`。
4. 保持“每一帧都发”的发送策略, 无目标帧也明确发送零量覆盖。
5. 让视觉仓库文档与主机侧测试一起收口到新协议边界。

## 非目标

1. 不在本轮把角度控制重新接回视觉输出。
2. 不为旧速度格式保留双发、兼容分支或自动回退逻辑。
3. 不把运行时代码拆成多文件结构。
4. 不扩展额外字段, 例如序号、阶段名、有效位或调试信息。
5. 不在本轮重写目标检测与目标选择规则。

## 规格原则

1. 最小正确改动优先: 只替换输出语义, 不顺手扩大到无关结构整理。
2. 视觉端职责保持稳定: 视觉端负责“这一帧该给什么控制量”, 底盘端负责消费位置命令并执行。
3. 主线文本保持最小: 每条消息只保留 `dx`、`dy` 和 `lock=0`。
4. 无目标语义显式化: 不依赖停发让底盘侧自行猜测当前状态。
5. 文档、测试与运行时代码同轮收口, 避免仓库内长期并存两套正式口径。

## 协议规格

### 串口边界

视觉端继续使用当前主通信串口与底盘侧 `UART6` 通信, 运行期只发送单行 ASCII 风格文本, 每条消息使用 `\r\n` 作为分帧结束。

### 主线格式

本轮正式输出固定为:

```text
dx=<dx>,dy=<dy>,lock=0
```

字段语义如下:

| 字段 | 含义 | 单位 | 说明 |
| :--- | :--- | :--- | :--- |
| `dx` | 车体系横向相对位置量 | 米 | 由视觉横向误差经 P 环与限幅后得到 |
| `dy` | 车体系纵向相对位置量 | 米 | 由视觉纵向误差经 P 环与限幅后得到 |
| `lock` | 覆盖式刷新修饰位 | 固定 `0` | 明确要求底盘侧按无锁覆盖语义处理 |

补充约束:

1. 每帧都发送完整的 `dx`、`dy` 与 `lock=0`。
2. 零值统一按紧凑文本输出为 `0`。
3. 不保留速度请求字段 `f`、`m`、`x`、`y`。
4. 不附带额外阶段名、序号或调试字段。

### 无目标与保持规则

下列场景统一发送:

```text
dx=0,dy=0,lock=0
```

适用场景包括:

1. 当前帧没有有效目标。
2. 当前帧已进入保持区。
3. 当前阶段只需要单轴动作时, 另一轴输出为 `0`。

本轮明确采用“发零量”作为静止语义, 不采用“停发”作为静止语义。

## 运行时职责边界

`main.py` 在本轮只承担以下职责:

1. 初始化串口与摄像头。
2. 持续抓图并提取候选目标。
3. 按既有规则选择当前帧最优目标。
4. 将视觉误差映射成二维位置式控制量。
5. 逐帧发送 `dx=<dx>,dy=<dy>,lock=0`。

`main.py` 在本轮不承担以下职责:

1. 发送旧速度请求。
2. 发送角度控制命令。
3. 发送额外查询、同步等待或状态协商命令。
4. 在运行期混用两套正式协议。

## 阶段与控制映射

### 阶段保留

本轮保留现有四段式判断边界:

1. `MARKER_MISSING`
2. `CENTER_HOLD`
3. `ALIGN_X`
4. `ALIGN_Y`

保留阶段名的目的仅限于视觉端内部判断与主机侧测试断言, 不进入串口正式载荷。

### 横向控制

横向控制继续使用“目标中心相对画面中心的偏差”作为输入。

当横向未进入死区时:

1. 进入 `ALIGN_X`
2. 只输出 `dx`
3. `dy` 固定为 `0`

横向 P 环输出在视觉端完成限幅后直接编码进 `dx` 字段。

### 纵向控制

纵向控制继续使用“目标面积相对目标面积的偏差”近似表达前后距离。

当横向已对齐且纵向未进入死区时:

1. 进入 `ALIGN_Y`
2. 只输出 `dy`
3. `dx` 固定为 `0`

纵向 P 环输出同样在视觉端完成限幅后编码进 `dy` 字段。

### 保持与丢目标

当目标丢失或已经进入保持区时:

1. 不累加历史控制量。
2. 不保留上一帧的非零命令。
3. 直接发送 `dx=0,dy=0,lock=0`。

## 参数策略

本轮保留当前顶部集中参数区的组织方式, 但参数语义需要收口为“位置式控制量”, 不再写成速度量。

参数边界如下:

1. 横向死区继续按像素误差配置。
2. 纵向目标继续按目标面积配置。
3. 横向 P 系数继续由像素误差映射到 `dx`。
4. 纵向 P 系数继续由面积误差映射到 `dy`。
5. 横向与纵向各自保留独立限幅参数, 用于约束单帧位置量上限。

本轮不引入积分、微分、历史累计或多阶段调度参数。

## 异常处理

1. 没有候选目标时, 发送零量。
2. 单帧误差异常偏大时, 先在视觉端限幅, 再发送。
3. 镜头校正若出现内存不足, 继续保持当前“跳过校正但不中断主循环”的处理方式。
4. 不通过“停发某些帧”表达异常状态, 以免底盘端把旧目标继续执行。

## 文档与测试收口

本轮实现严格按 TDD 进行, 先改测试再改实现。

### 测试收口范围

1. 单元测试改为约束 `format_vision_frame()` 输出 `dx=<dx>,dy=<dy>,lock=0`。
2. 单元测试改为约束横向阶段只输出 `dx`, 纵向阶段只输出 `dy`。
3. 单元测试改为约束无目标和保持阶段都输出零量位置命令。
4. 契约测试改为拦截旧速度协议字段与旧文档口径。
5. 契约测试改为要求 `README.md` 与 `docs/Protocol.md` 都明确使用 `dx/dy/lock=0` 口径。

### 文档收口范围

1. `README.md` 改为描述“视觉端逐帧发送位置式命令”。
2. `docs/Protocol.md` 改为描述 `dx=<dx>,dy=<dy>,lock=0` 的正式协议。
3. 文档中不再把 `x/y` 解释成速度量。

## 风险与控制

### 风险一: 单帧位置量过大导致动作跳变

控制方式:

1. 保留横向和纵向各自的单帧限幅。
2. 第一轮只做 P 环, 不叠加额外放大机制。

### 风险二: 无目标停发导致底盘继续执行旧目标

控制方式:

1. 无目标固定发送零量。
2. 保持区同样发送零量, 统一静止语义。

### 风险三: 仓库文档与测试仍保留速度口径

控制方式:

1. 文档与测试和运行时代码同轮改动。
2. 契约测试显式拦截旧速度字段和旧说明文字。

## 验收标准

1. `main.py` 仍为单文件唯一运行入口。
2. 视觉端每帧输出正式文本 `dx=<dx>,dy=<dy>,lock=0`。
3. `ALIGN_X` 仅输出横向位置量, `ALIGN_Y` 仅输出纵向位置量。
4. 无目标与保持状态都明确输出 `dx=0,dy=0,lock=0`。
5. 仓库内正式文档与主机侧测试都收口到位置式输出口径。
