# OpenArt 与 RT1021 视觉通信协议

## 1. 文档目的

本文档只描述当前主线已经采用的视觉通信方式：OpenArt 持续向 RT1021 发送速度式命令文本。

本文只保留当前主线所需信息，不展开非主线流程或额外协议分支。

## 2. 主链路概览

### 2.1 串口角色

| 链路 | OpenArt 侧 | RT1021 侧 | 用途 |
| :--- | :--- | :--- | :--- |
| 主通信链路 | `UART(2)` | `UART6` | 直接发送速度命令 |

### 2.2 传输约定

- 默认波特率: `115200`
- 文本编码: 以 ASCII 风格单行文本为主
- 分帧方式: 按行收发，每条消息以 `\r\n` 结束
- 主机制: OpenArt 每抓一帧就发送最新速度命令，RT1021 持续消费最新速度命令
- 回传原则: 只关心最新一帧，不依赖历史帧逐条确认

## 3. 速度式命令格式

### 3.1 合法载荷

当前主线固定使用以下文本格式：

```text
vx=<vx>,vy=<vy>
```

字段说明如下：

| 字段 | 含义 | 单位 | 说明 |
| :--- | :--- | :--- | :--- |
| `vx` | 横向速度量 | 浮点文本 | `vx` 表示发给底盘的横向速度量 |
| `vy` | 纵向速度量 | 浮点文本 | `vy` 表示发给底盘的纵向速度量 |

补充约定：

- 视觉端始终发送完整的 `vx=...,vy=...`
- 无目标或保持阶段时发送 `vx=0,vy=0`
- OpenArt 直接承担跟随阶段判断和控制量生成
- 当前阶段名固定为 `MARKER_MISSING`、`CENTER_HOLD`、`ALIGN_X`、`ALIGN_Y`
- `ALIGN_X` 阶段只输出横向速度量，`ALIGN_Y` 阶段只输出纵向速度量
- `CENTER_HOLD` 和 `MARKER_MISSING` 都输出零量
- 当前主线直接对齐底盘已经支持的速度命令入口

### 3.2 合法示例

```text
vx=0.12,vy=0
vx=0,vy=0
```

## 4. 消费方式

RT1021 对速度式命令按以下方式处理：

- 只保留最近一次收到的合法速度命令
- 新请求到来后直接覆盖旧请求
- 视觉端无需等待逐帧确认再发送下一帧
- `vx=0,vy=0` 明确表示当前拍不驱动车体平移
- 视觉端直接给出底盘应执行的二维速度量

这条链路的核心含义是：

> OpenArt 持续提供“这一拍该怎么走”，RT1021 直接消费并执行当前已支持的速度命令入口。

## 5. 视觉端边界

当前主线下，OpenArt 只负责：

- 图像采集
- `red` 目标检测
- 目标选择
- 计算横向中心偏差
- 计算纵向面积误差
- 判断当前跟随阶段
- 生成 `vx=<vx>,vy=<vy>`
- 持续发送最新速度命令

当前主线下，OpenArt 不负责：

- 辅车协议扩展
- 底盘控制编排

## 6. 发送要求

为了避免误解或误触发，视觉端发送时应遵守以下要求：

- 只发送当前主线约定的 `vx/vy`
- 不要在视觉帧中混入其他控制含义字段
- 每次发送都应是一条完整、可独立解析的单行文本

### 6.1 无目标规则

无目标或保持阶段时，视觉端发送明确的零速度命令。

当前零速度命令固定为：

```text
vx=0,vy=0
```

也就是说：

- 横向未对齐时，持续发送只含横向速度量的合法请求
- 纵向未对齐时，持续发送只含纵向速度量的合法请求
- 无目标或进入保持阶段时，持续发送 `vx=0,vy=0`

以上规则体现的就是当前主线：逐帧发送速度式命令文本，并直接对齐底盘已支持的速度命令入口。
