# OpenArt 与 RT1021 视觉通信协议

## 1. 文档目的

本文档只描述当前主线已经采用的视觉通信方式：OpenArt 持续向 RT1021 发送速度模式请求文本。

本文只保留当前主线所需信息，不展开非主线流程或额外协议分支。
除启动阶段可选一次 `reset=1` 外，当前协议不额外引入第二套视觉发包字段族。

## 2. 主链路概览

### 2.1 串口角色

| 链路 | OpenArt 侧 | RT1021 侧 | 用途 |
| :--- | :--- | :--- | :--- |
| 主通信链路 | `UART(2)` | `UART6` | 直接发送辅车速度模式请求 |

### 2.2 传输约定

- 默认波特率: `115200`
- 文本编码: 以 ASCII 风格单行文本为主
- 分帧方式: 按行收发，每条消息以 `\r\n` 结束
- 主机制: OpenArt 持续发送最新速度模式请求，RT1021 持续消费最新速度模式请求
- 回传原则: 只关心最新一帧，不依赖历史帧逐条确认
- 唯一例外: 启动阶段允许可选发送一次 `reset=1`，用于进入干净运行态；除此之外主线仍然是持续发送速度模式请求文本

## 3. 速度模式请求格式

### 3.1 合法载荷

当前主线速度模式请求固定使用以下文本格式：

```text
f=1,m=1,x=<x>,y=<y>
```

字段说明如下：

| 字段 | 含义 | 单位 | 说明 |
| :--- | :--- | :--- | :--- |
| `f` | 速度模式请求标记 | 固定为 `1` | `f=1,m=1` 表示这是一条速度模式入口请求 |
| `m` | 模式标记 | 固定为 `1` | `m=1` 表示当前报文走辅车现成速度模式入口 |
| `x` | 横向速度 | 浮点文本 | `x` 表示发给辅车的横向速度 |
| `y` | 纵向速度 | 浮点文本 | `y` 表示发给辅车的纵向速度 |

补充约定：

- 视觉端始终发送完整的 `f=1,m=1,x=...,y=...`
- 无目标或保持阶段时发送 `x=0,y=0`
- OpenArt 直接承担跟随阶段判断和控制量生成
- 当前阶段名固定为 `MARKER_MISSING`、`CENTER_HOLD`、`ALIGN_X`、`ALIGN_Y`
- `ALIGN_X` 阶段只输出横向控制量，`ALIGN_Y` 阶段只输出纵向控制量
- `CENTER_HOLD` 和 `MARKER_MISSING` 都输出零速度
- 当前主线直接对齐辅车已经支持的速度模式入口

### 3.2 合法示例

```text
f=1,m=1,x=1.2,y=0
f=1,m=1,x=0,y=0
```

## 4. 消费方式

RT1021 对速度模式请求按以下方式处理：

- 只保留最近一次收到的合法速度请求
- 新请求到来后直接覆盖旧请求
- 视觉端无需等待逐帧确认再发送下一帧
- `x=0,y=0` 明确表示当前拍不驱动车体平移
- 视觉端直接给出辅车应执行的平面速度量

这条链路的核心含义是：

> OpenArt 持续提供“这一拍该怎么走”，RT1021 直接消费并执行当前已支持的速度模式入口。

## 5. 视觉端边界

当前主线下，OpenArt 只负责：

- 图像采集
- `red` 目标检测
- 目标选择
- 计算横向中心偏差
- 计算纵向面积误差
- 判断当前跟随阶段
- 生成 `f=1,m=1,x=<x>,y=<y>`
- 持续发送最新速度模式请求

当前主线下，OpenArt 不负责：

- 辅车协议扩展
- 底盘控制编排

## 6. 发送要求

为了避免误解或误触发，视觉端发送时应遵守以下要求：

- 只发送当前主线约定的 `f/m/x/y`
- 除启动阶段可选一次 `reset=1` 外，不发送任何查询、状态切换或控制字段
- 不要在视觉帧中混入其他控制含义字段
- 每次发送都应是一条完整、可独立解析的单行文本

### 6.1 启动复位例外

当前实现只保留一个受限例外：启动阶段可选发送一次 `reset=1`。

- 这条消息只允许出现在启动阶段
- 这条消息最多发送一次
- 它用于让 RT1021 进入干净运行态，不改变“持续发送速度模式请求文本”作为主线机制
- 除这一条外，视觉端不发送任何额外协议动作

### 6.2 无目标规则

无目标或保持阶段时，视觉端发送明确的零速度请求。

当前零速度请求固定为：

```text
f=1,m=1,x=0,y=0
```

也就是说：

- 横向未对齐时，持续发送只含横向速度的合法请求
- 纵向未对齐时，持续发送只含纵向速度的合法请求
- 无目标或进入保持阶段时，持续发送 `f=1,m=1,x=0,y=0`

## 7. 最小示例

```text
f=1,m=1,x=1.2,y=0
f=1,m=1,x=0,y=0
```

以上示例体现的就是当前主线：持续发送速度模式请求文本，并直接对齐辅车已支持的速度模式入口。
