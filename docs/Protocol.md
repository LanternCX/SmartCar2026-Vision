# OpenART 与 RT1021 视觉通信协议

## 1. 文档目的

本文档描述 OpenART 持续向 RT1021 发送视觉速度修正短包的通信方式。

本文只保留视觉主链路所需信息，不展开非主线流程或额外协议分支。

## 2. 主链路概览

### 2.1 串口角色

| 链路 | OpenART 侧 | RT1021 侧 | 用途 |
| :--- | :--- | :--- | :--- |
| 视觉主链路 | `UART(2)` | `UART6` | 发送视觉速度修正量 |

### 2.2 传输约定

- 默认波特率: `115200`
- 文本编码: ASCII 单行文本
- 分帧方式: 按行收发，每条消息以 `\r\n` 结束
- 主机制: OpenART 每抓一帧就发送最新速度修正短包，RT1021 持续消费最新速度修正短包
- 确认方式: 高频视觉数据流不逐帧确认

## 3. 速度短包格式

### 3.1 合法载荷

视觉主链路固定使用以下文本格式：

```text
v,<vx>,<vy>
```

字段说明如下：

| 位置 | 字段 | 含义 | 说明 |
| :--- | :--- | :--- | :--- |
| 1 | `v` | 速度数据流短包类型 | 固定为 `v` |
| 2 | `vx` | 车体系 x 方向视觉速度修正量 | 浮点文本 |
| 3 | `vy` | 车体系 y 方向视觉速度修正量 | 浮点文本 |

补充约定：

- 视觉端始终发送完整的 `v,<vx>,<vy>`
- `UART6` 视觉链路不发送 `omega`
- 无目标或保持阶段时发送 `v,0,0`
- OpenART 直接承担跟随阶段判断和控制量生成
- 阶段名固定为 `MARKER_MISSING`、`CENTER_HOLD`、`ALIGN_X`、`ALIGN_Y`、`ALIGN_XY`
- `ALIGN_X` 阶段只输出横向速度修正量，`ALIGN_Y` 阶段只输出纵向速度修正量
- `CENTER_HOLD` 和 `MARKER_MISSING` 都输出零量

### 3.2 合法示例

```text
v,0.12,0
v,0,0
v,-0.8,0.45
```

## 4. 消费方式

RT1021 对视觉速度短包按以下方式处理：

- 只保留最近一次收到的合法速度修正短包
- 新请求到来后直接覆盖旧请求
- 视觉端无需等待逐帧确认再发送下一帧
- `v,0,0` 明确表示当前拍不驱动车体平移
- 视觉端直接给出底盘应执行的二维速度修正量

这条链路的核心含义是：

> OpenART 持续提供“这一拍该怎么修正”，RT1021 直接消费并执行最新视觉速度修正量。

## 5. 视觉端边界

OpenART 负责：

- 图像采集
- `red` 目标检测
- 目标选择
- 计算横向中心偏差
- 计算纵向尺度误差
- 判断当前跟随阶段
- 生成 `v,<vx>,<vy>`
- 持续发送最新速度修正短包

OpenART 不负责：

- 状态同步
- 确认包处理
- 事件回报
- 底盘控制编排

## 6. 发送要求

为了避免误解或误触发，视觉端发送时应遵守以下要求：

- 只发送视觉主链路约定的 `v,<vx>,<vy>`
- 不在视觉帧中混入其他控制含义字段
- 每次发送都应是一条完整、可独立解析的单行文本

### 6.1 无目标规则

无目标或保持阶段时，视觉端发送明确的零速度修正短包。

零速度修正短包固定为：

```text
v,0,0
```

也就是说：

- 横向未对齐时，持续发送只含横向速度修正量的合法请求
- 纵向未对齐时，持续发送只含纵向速度修正量的合法请求
- 无目标或进入保持阶段时，持续发送 `v,0,0`
