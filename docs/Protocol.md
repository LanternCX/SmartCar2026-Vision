# OpenArt 与 RT1021 视觉通信协议

## 1. 文档目的

本文档只描述当前主线已经采用的视觉通信方式：OpenArt 持续直接向 RT1021 回传最新目标框。

本文只保留当前主线所需信息，不展开非主线流程或动作编排细节。
除启动阶段可选一次 `reset=1` 外，当前协议不允许视觉端发送任何非观测动作。

## 2. 主链路概览

### 2.1 串口角色

| 链路 | OpenArt 侧 | RT1021 侧 | 用途 |
| :--- | :--- | :--- | :--- |
| 主通信链路 | `UART(2)` | `UART6` | 持续视觉观测上报 |

### 2.2 传输约定

- 默认波特率: `115200`
- 文本编码: 以 ASCII 风格单行文本为主
- 分帧方式: 按行收发，每条消息以 `\r\n` 结束
- 主机制: OpenArt 持续发送最新观测，RT1021 持续消费最新观测
- 回传原则: 只关心最新一帧，不依赖历史帧逐条确认
- 唯一例外: 启动阶段允许可选发送一次 `reset=1`，用于进入干净运行态；除此之外主线仍然是持续直接回传最新观测

## 3. 视觉帧格式

### 3.1 合法载荷

当前主线视觉帧固定使用四个字段：

```text
left=<num>,top=<num>,right=<num>,bottom=<num>
```

字段说明如下：

| 字段 | 含义 | 单位 | 说明 |
| :--- | :--- | :--- | :--- |
| `left` | 目标框左边界 | 像素 | 相对图像左边界 |
| `top` | 目标框上边界 | 像素 | 相对图像上边界 |
| `right` | 目标框右边界 | 像素 | 相对图像左边界 |
| `bottom` | 目标框下边界 | 像素 | 相对图像上边界 |

补充约定：

- 四个值都必须能解析为数字
- 单帧只表达一个当前选中的目标框
- 文档只约定输出格式，不约定 OpenArt 内部如何完成检测与筛选

### 3.2 合法示例

```text
left=145,top=20,right=175,bottom=240
left=146,top=20,right=174,bottom=239
left=147,top=21,right=173,bottom=240
```

## 4. 消费方式

RT1021 对视觉帧按以下方式处理：

- 只保留最近一次收到的合法观测
- 新观测到来后直接覆盖旧观测
- 视觉端无需等待逐帧确认再发送下一帧
- 视觉端只负责持续提供观测，不负责后续控制组织

这条链路的核心含义是：

> OpenArt 持续提供“现在看到了什么”，RT1021 负责决定“接下来怎么做”。

## 5. 视觉端边界

当前主线下，OpenArt 只负责：

- 图像采集
- 目标检测
- 目标选择
- 持续发送最新目标框

当前主线下，OpenArt 不负责：

- 任务状态机
- 底盘控制决策
- 动作阶段切换
- 底盘控制编排

## 6. 发送要求

为了避免误解或误触发，视觉端发送时应遵守以下要求：

- 只发送当前主线约定的 `left/top/right/bottom`
- 除启动阶段可选一次 `reset=1` 外，不发送任何查询、状态切换或控制字段
- 不要在视觉帧中混入其他控制含义字段
- 每次发送都应是一条完整、可独立解析的单行文本

### 6.1 启动复位例外

当前实现只保留一个受限例外：启动阶段可选发送一次 `reset=1`。

- 这条消息只允许出现在启动阶段
- 这条消息最多发送一次
- 它用于让 RT1021 进入干净运行态，不改变“持续直接回传最新目标框”作为主线机制
- 除这一条外，视觉端不发送任何非观测动作

### 6.2 无目标规则

无目标时，视觉端不发送任何伪帧，也不发送用于占位的假坐标、空框或其他替代格式。

接收端应以“在超时时间内没有收到新的合法视觉帧”作为目标丢失判定条件。

也就是说：

- 有目标时，持续发送最新合法目标框
- 无目标时，直接停止发送视觉帧
- 目标是否丢失，由接收端按超时规则自行判定

## 7. 最小示例

```text
left=145,top=20,right=175,bottom=240
left=146,top=20,right=174,bottom=239
left=147,top=21,right=173,bottom=240
```

以上示例体现的就是当前主线：持续直接回传最新目标框。
